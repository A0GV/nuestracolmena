## Necesita tu revisión

- **Query API:** ahora devuelve arrays como TheHive (antes `{items,total}`); la web no la usaba.
- **`listAction`** devuelve un objeto (no array) porque el nodo de n8n lee `response.status` al hacer polling del responder.
- En webhooks formato TheHive, acciones internas (cerrar, importar, fusionar…) salen como `update` con `details.operation` = acción real, porque el trigger de n8n solo entiende create/update/delete.
- SLA: `businessHours` (horario laboral) no está implementado; el filtro por plantilla no aplica porque los casos no guardan su plantilla. Si varias reglas coinciden gana la de menor `order`.
- **Permisos en la VM:** tras actualizar, los perfiles `analyst` ya no tienen `manageConfig`. Si la API key de n8n/Wazuh (`MYHIVE_N8N_KEY`) es de un analista, sigue sirviendo para crear alertas e invocar funciones, pero `register-connectors.mjs` necesita la key de un admin u org-admin.
- Se añadió `DELETE /api/v1/misp/events/:id` (permiso manageShare) para que las pruebas limpien lo que exportan.
- Correo reportado: se deduplica por el Message-ID del reenvío (si dos personas reportan el mismo phishing salen dos alertas, enlazadas por correlación).
- El tipo de un endpoint no se puede cambiar al editarlo (se crea otro).
- Al cerrar un caso por la API v4, `impactStatus` se acepta pero no se guarda aparte.
- `similarAlerts`/`similarCases` en la Query API devuelven `[]` hasta la tarea 6.
